# SUPERFIX CardNews Factory PRD

## 1. 프로젝트 개요

### 프로젝트명

SUPERFIX CardNews Factory

### 목적

SUPERFIX 에어피팅 및 공압부품 상품 데이터를 기반으로 인스타그램 카드뉴스를 자동 생성하는 내부 운영 시스템을 구축한다.

AI가 콘텐츠를 생성하는 것이 목표가 아니다.

상품 DB + 제품 이미지 + 템플릿을 조합하여 수천~수만 개 상품의 카드뉴스를 자동 생성하는 것이 핵심이다.

### 배경

현재 SNS 카드뉴스 제작 과정은 전부 수작업이다.

```
상품 등록
→ 상세페이지 제작
→ 카드뉴스 기획
→ 디자인 제작
→ 인스타 업로드
```

이 흐름을 다음과 같이 자동화한다.

```
상품 데이터 1건 선택
→ 템플릿 선택
→ 카드뉴스 5장 자동 생성
→ PNG 다운로드
→ 인스타 업로드
```

### 핵심 목표

상품 데이터 1건 입력 → 카드뉴스 5장 자동 생성 → PNG 다운로드 → 인스타 업로드

## 2. 핵심 철학

### AI는 보조 기능이다

주 시스템은 다음 흐름으로 동작한다.

```
상품 DB
↓
템플릿 엔진
↓
카드뉴스 생성
```

AI가 없어도 카드뉴스 생성이 가능해야 한다.

AI는 문구 개선 등 선택적 보조 역할만 수행한다.

### 디자인은 고정하고 데이터만 변경한다

매 상품마다 새로 디자인하지 않는다.

고정된 템플릿에 다음 요소만 교체한다.

- 제품 이미지
- 모델명
- 규격 (튜브 사이즈, 나사 규격)
- 메인 카피 문구
- 사용 분야

## 4. 기술 스택

기존 프로젝트(One Touch Fitting) 스택을 그대로 활용한다.

### Frontend

- Next.js 15 (App Router)
- TypeScript
- TailwindCSS
- shadcn/ui (new-york 스타일)

### Backend

- Next.js API Routes (Server Actions)
- Supabase (DB + 인증)

### 이미지 렌더링

- Playwright: HTML → PNG 렌더링 (기존 상세페이지 생성 방식 재사용)
- 제품 이미지는 `my_products.image_path` 외부 URL을 그대로 사용

### AI (선택 기능)

- Claude Sonnet: 카드뉴스 문구 개선 보조

### 인프라

- Vercel (배포)
- Supabase Storage (생성된 PNG 저장 전용 — 제품 이미지 업로드 없음)

## 5. 기능 요구사항

### 5-1. 상품 관리

기존 `my_products` 테이블(536개 제품)을 기반으로 동작한다.

| 기능 | 설명 |
|------|------|
| 상품 목록 조회 | 전체 상품 목록, 카테고리/타입 필터 |
| 상품 검색 | 모델명, 제품명 검색 |
| 상품 상세 조회 | 단일 상품의 전체 데이터 확인 |
| 상품 등록 | 신규 상품 데이터 입력 |
| 상품 수정 | 기존 상품 데이터 편집 |
| CSV/XLSX 일괄 업로드 | 다수 상품을 파일로 일괄 등록 |

### 5-2. 이미지 관리

별도 이미지 업로드 없음. `my_products.image_path`에 저장된 외부 URL을 그대로 사용한다.

| 기능 | 설명 |
|------|------|
| 이미지 미리보기 | 상품 선택 시 `image_path` URL로 이미지 미리 확인 |
| 누락 이미지 확인 | `image_path`가 null인 상품 목록 표시 |

### 5-3. 카드뉴스 템플릿 관리

| 기능 | 설명 |
|------|------|
| 템플릿 3종 선택 | TYPE A (문제 해결형), TYPE B (규격 설명형), TYPE C (제품 소개형) |
| 슬라이드 구성 확인 | 각 템플릿의 5장 슬라이드 구성 미리보기 |
| 자동 문구 규칙 적용 | 상품 타입(PC/PL/PY/PB/PWT)에 따른 기본 문구 자동 매핑 |
| 문구 수동 편집 | 자동 생성된 문구를 사용자가 직접 수정 |
| AI 문구 개선 (선택) | Claude Sonnet을 활용한 문구 개선 제안 |

### 5-4. 카드뉴스 생성

| 기능 | 설명 |
|------|------|
| 단일 상품 생성 | 상품 1건 선택 후 카드뉴스 5장 생성 |
| 미리보기 | PNG 생성 전 HTML 기반 실시간 미리보기 |
| PNG 렌더링 | Playwright로 HTML → PNG 변환 (1080x1350) |
| 생성 이력 저장 | 생성된 카드뉴스 작업 이력을 DB에 저장 |

### 5-5. 다운로드

| 기능 | 설명 |
|------|------|
| 개별 슬라이드 다운로드 | 5장 중 선택한 슬라이드만 다운로드 |
| ZIP 일괄 다운로드 | 5장 전체를 ZIP으로 묶어 다운로드 |
| 생성 결과 목록 조회 | 과거 생성된 카드뉴스 이력 확인 및 재다운로드 |

## 7. 카드뉴스 생성 플로우

### 전체 흐름

```
[상품 관리 페이지]
상품 선택 (모델명 클릭 또는 체크박스)
↓
[카드뉴스 생성 페이지]
템플릿 선택 (TYPE A / B / C)
↓
문구 자동 생성
(product_type → copy_rules 조회 → 각 슬라이드 문구 매핑)
↓
문구 수동 편집 (선택)
↓
AI 문구 개선 요청 (선택 - Claude Sonnet)
↓
HTML 미리보기 (1080x1350 비율 확인)
↓
PNG 생성 버튼 클릭
↓
서버에서 Playwright 실행
(HTML 렌더링 → 5장 PNG 생성)
↓
Supabase Storage 저장
↓
card_news_jobs 레코드 생성 (status: done)
↓
[다운로드 페이지]
개별 PNG 또는 ZIP 다운로드
```

### 문구 자동 생성 규칙

상품의 `type` 필드를 기준으로 `copy_rules` 테이블에서 슬라이드별 기본 문구를 조회한다.

| 제품 타입 | 슬라이드 1 기본 문구 |
|----------|-------------------|
| PC | 4mm 호스 연결, 뭘 써야 할까? |
| PL | 좁은 공간이라면? |
| PY | 호스를 분기해야 한다면? |
| PB | 배관 방향을 바꿔야 한다면? |
| PWT | 2개 방향을 동시에 연결해야 한다면? |

## 8. 카드뉴스 템플릿 3종 상세 스펙

### TYPE A - 문제 해결형

문제 제기 → 위험성 강조 → 제품 소개 → 활용 분야 → 브랜드 마무리 구성

| 슬라이드 | 역할 | 주요 요소 |
|---------|------|---------|
| 1장 | 문제 제기 | 메인 카피 (예: "4mm 호스 연결, 뭘 써야 할까?"), 배경 이미지 |
| 2장 | 위험성 강조 | 서브 카피 (예: "잘못 선택하면 에어 누설 발생"), 경고 아이콘 |
| 3장 | 제품 사용 예시 | 제품 이미지, 모델명 (예: PC04-M5), 간략 스펙 |
| 4장 | 사용 분야 | 활용 예시 텍스트 (공압배관, 자동화설비 등) |
| 5장 | 브랜드 마무리 | SUPERFIX 로고, CTA (daitem.co.kr) |

### TYPE B - 규격 설명형

규격 비교 의문 → 규격 설명 → 사용 예시 → 추천 제품 → 브랜드 마무리 구성

| 슬라이드 | 역할 | 주요 요소 |
|---------|------|---------|
| 1장 | 규격 비교 의문 | 메인 카피 (예: "PT1/8 PT1/4 무슨 차이일까?") |
| 2장 | 규격 설명 | 규격 비교 텍스트, 치수 정보 |
| 3장 | 사용 예시 | 실제 사용 환경 이미지 또는 텍스트 설명 |
| 4장 | 추천 제품 | 제품 이미지, 모델명, 구매 안내 |
| 5장 | 브랜드 마무리 | SUPERFIX 로고, CTA (daitem.co.kr) |

### TYPE C - 제품 소개형

제품명 직접 노출 → 특징 → 규격 정보 → 사용 분야 → 브랜드 마무리 구성

| 슬라이드 | 역할 | 주요 요소 |
|---------|------|---------|
| 1장 | 제품 직접 소개 | 제품 이미지, 모델명 (예: PC04-M5) |
| 2장 | 주요 특징 | 원터치 연결, 밀폐성, 내구성 등 4가지 특징 |
| 3장 | 규격 정보 | 튜브 규격, 나사 규격, 압력/온도 스펙표 |
| 4장 | 사용 분야 | 활용 환경 텍스트 (공압배관, 자동화설비, 실린더 등) |
| 5장 | 브랜드 마무리 | SUPERFIX 로고, CTA (daitem.co.kr) |

## 10. 화면 구성 (라우트별 UI)

### /cardnews/dashboard - 전체 현황

- 전체 상품 수, 이미지 보유 상품 수, 생성된 카드뉴스 수 통계 카드
- 최근 생성된 카드뉴스 목록 (최대 10건)
- 빠른 생성 진입 버튼

### /cardnews/products - 상품 관리

- 상품 목록 테이블 (모델명, 제품명, 타입, 이미지 유무, 생성 여부)
- 카테고리/타입 필터, 모델명 검색
- 상품 클릭 시 카드뉴스 생성 페이지로 이동
- CSV/XLSX 일괄 업로드 버튼

### /cardnews/images - 이미지 현황

- 상품별 `image_path` URL 이미지 미리보기 (그리드 뷰)
- `image_path`가 null인 상품 목록 탭 (이미지 누락 현황 파악용)

### /cardnews/generate - 카드뉴스 생성

**Step 1: 상품 선택**

- 상품 검색 및 선택 UI
- 선택된 상품의 기본 정보 미리 표시 (모델명, 튜브 규격, 나사 규격, 이미지)

**Step 2: 템플릿 선택**

- TYPE A / B / C 카드 형태로 선택
- 각 타입의 슬라이드 구성 설명 표시

**Step 3: 문구 확인 및 편집**

- 슬라이드별 자동 생성된 문구 표시
- 인라인 편집 가능
- AI 문구 개선 버튼 (선택 기능)

**Step 4: 미리보기**

- 5장 슬라이드 HTML 미리보기 (1080x1350 비율)
- 슬라이드 간 전환 네비게이션

**Step 5: PNG 생성**

- 생성 버튼 클릭 → 서버에서 Playwright 실행
- 진행 상태 표시 (로딩 인디케이터)
- 완료 시 다운로드 페이지로 자동 이동

### /cardnews/download - 생성 결과 다운로드

- 생성된 카드뉴스 이력 목록 (최신순)
- 5장 슬라이드 썸네일 미리보기
- 개별 PNG 다운로드 버튼
- ZIP 전체 다운로드 버튼
- 생성 일시, 상품명, 템플릿 타입 표시

### /cardnews/settings - 브랜드 설정

- 브랜드명, 로고 이미지 설정
- 기본 CTA URL 설정 (현재: daitem.co.kr)
- Primary/Secondary 컬러 설정
- 기본 폰트 설정

| 템플릿 3종 | TYPE A, B, C 슬라이드 구성 |
| 자동 문구 생성 | product_type 기반 copy_rules 조회 |
| HTML 미리보기 | 생성 전 시각적 확인 |
| PNG 렌더링 | Playwright HTML → PNG (1080x1350) |
| ZIP 다운로드 | 5장 일괄 다운로드 |
| 생성 이력 관리 | card_news_jobs 테이블 저장 |

### MVP 제외 항목

| 항목 | 제외 이유 |

## 12. 개발 단계별 순서

### Phase 1 - 상품 DB 및 이미지 관리

목표: 상품 데이터와 이미지를 시스템에서 관리할 수 있는 상태

```
1. /cardnews 라우트 그룹 생성 (기존 시스템과 분리)
2. 상품 목록 페이지 (/cardnews/products)
   - 기존 my_products 데이터 연동
   - image_path URL 이미지 미리보기
   - image_path 누락 상품 표시
3. 이미지 현황 페이지 (/cardnews/images)
   - image_path 기반 그리드 뷰
   - 누락 상품 목록 탭
4. 대시보드 (/cardnews/dashboard)
   - 기본 통계 카드
```

### Phase 2 - 카드뉴스 템플릿 및 PNG 생성

목표: 실제로 카드뉴스 5장을 PNG로 생성하고 다운로드할 수 있는 상태

```
1. card_news_templates 테이블 생성 및 TYPE A/B/C 데이터 초기화
2. copy_rules 테이블 생성 및 타입별 문구 초기화
3. card_news_jobs 테이블 생성
4. 카드뉴스 생성 페이지 (/cardnews/generate)
   - Step 1~5 Stepper UI
   - HTML 슬라이드 컴포넌트 (TYPE A/B/C)
   - 미리보기 기능
5. PNG 렌더링 API Route
   - Playwright 실행 (기존 상세페이지 렌더러 재사용)
   - Supabase Storage 저장
   - card_news_jobs 레코드 생성
6. 다운로드 페이지 (/cardnews/download)
   - 이력 목록 및 ZIP 다운로드
```

### Phase 3 - AI 문구 개선 (선택 기능)

목표: Claude Sonnet으로 카드뉴스 문구 품질을 선택적으로 개선

```
1. Claude Sonnet API 연동
2. 문구 개선 프롬프트 설계
   - 상품 타입, 모델명, 규격 정보를 컨텍스트로 전달
   - 슬라이드별 개선 문구 반환
3. /cardnews/generate Step 3에 AI 문구 개선 버튼 추가
4. 사용자가 AI 제안과 기본 문구 중 선택 가능한 UI
```

## 기존 시스템 연동 포인트

이 기능은 기존 One Touch Fitting 시스템에 통합된다.

| 기존 시스템 | 연동 방식 |
|------------|---------|
| Supabase 인증 | 그대로 재사용 (로그인 필수) |
| my_products 테이블 | 상품 데이터 소스로 직접 연동 |
| Playwright 렌더러 | 기존 상세페이지 생성 코드 재사용 |
| Supabase Storage | 생성된 PNG 저장 전용 버킷 신규 생성 (제품 이미지 업로드 없음) |
| shadcn/ui 컴포넌트 | 기존 UI 컴포넌트 재사용 |
